What a path is.
A path keeps a record of finished work and reads the record back to decide whether the work runs again.
Its reuse identity is what the record is found by and compared with.
Its retry rule says when a found record is reused, when the work runs again and when the request is refused.
Its readers are the production declarations that enter it.

What a size is.
A path's size is the syntax nodes of its counted declarations.
A declaration is counted when it exists to compute the key, to read the stored record, to decide between reuse and running, or to write the record.
Only a function, a method or a package variable is counted.
The record's type, its codec and the codec's checks describe the record and are not counted.
A declaration that runs the work and holds a line of the four is named beside the path and is not counted, because it is the machinery that then trains or executes.
A declaration is counted whole, with its doc comment, and in one path only.
A node is counted as a commit's checks count production code, from a parse with comments (internal/landing/rules.go#writtenNodes).
A whole file is a file that holds its path's declarations, their record and nothing of another mechanism.
The nodes of a path's whole files are what deleting those files would take out of the production count.
The sizes hold at every commit, because the test counts them again.
Which declarations are counted is a judgement of the session that wrote this record.
