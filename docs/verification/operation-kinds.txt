The shape reading labels the family of switches over the tensor operations internal/tensor.Op, and the part on the switches gives its figures.

Where an operation is decided.
An operation is a constant of internal/tensor/tensor.go and a row of internal/tensor/operation.go#operationDescriptors, which names it, classes it, claims its backends and names the family of device launchers it belongs to.
Its output shape is decided once, by its method of the graph builder in internal/tensor, and none of the ten switches decides a shape.
Its attribute type says which values it carries, and that type's validFor method, or the list of operations that carry none, says which operations may carry it.
Its host arithmetic is a case of the reference executor, and its device launch is a case of one family's launcher in internal/cuda/executor, with its kernel in the kernel manifest.
An operation whose attributes change at each decode step (a row lookup, a rotary encoding, attention and a cache append) is also a case of the rule for per-step overrides and of the decode session's plan.
The line operations-by-switches counts, for each number of switches, the operations that many of the ten switches name.
No operation is named by more than four, and the operations named by four are the ones with per-step attributes.
An operation with attributes is named by its host case and its device case, and one with none is also named by the list of operations that carry none.
The exceptions are the two views (reshape and flat_slice), which have no host case, input, which has no arithmetic, and moe, whose device launcher switches on it alone and so falls outside the family.
So the ten switches split the operations between the host, the device families, the attribute contract and the per-step rules, and an operation is a case of at most four of them.
The plan's statement that adding or changing an operation means ten places counts the switches and not the places of one operation.

How each switch was read.
Each switch was read whole, case by case, and its reading is its entry's decides, row and table.
Its counts are what the test counts again from its syntax.
A dispatch line is a line a table deletes from a switch outright, which is the line it opens on, a case's header, a default of one statement, or its closing brace.
A recheck is an if that refuses a failed type assertion of an operation's attributes, and a dimension check and a count check are an if that returns the error of narrowing a shape to the 32-bit words a kernel takes.
Every node passes internal/tensor/attributes.go#ValidateOperationAttributes, which refuses a pointer to an attribute type, when the builder adds it, when its program compiles and when the reference executor runs it alone, so an executor's type assertion cannot fail.
Every device launch's shape passes internal/cuda/executor/fallback.go#checkLaunchWords when its graph compiles, so a launch's narrowing to 32-bit words cannot fail.
TestNoLaunchRepeatsACompileCheck counts the rechecks, the dimension checks and the count checks of the ten switches with the same reading, and requires none.

The table this reading prices.
Package tensor cannot hold the host or the device entries, because internal/tensor/reference and internal/cuda/executor import it.
So the table is three tables, one in each of the three packages, each indexed by operation.
In package tensor, the descriptors gain a column for the attribute type, which replaces the list of operations that carry none and each attribute type's validFor.
In the reference executor, one entry per operation holds its host arithmetic, a case of one statement folded onto its row and a longer case as a function literal.
In the CUDA executor, one entry per operation holds its launch and, for an elementwise operation, its kernel.
Those entries replace the descriptors' launcher-family column, the table of launcher families (internal/cuda/executor/launch.go#nodeLaunchers), the families' switches and the if chains that pick a kernel by operation.
The seven attribute types with per-step values gain one interface in package tensor, whose methods replace the rule for per-step overrides.
The decode session's switch stays, because its choice of nodes reads the decode graph and its slot kinds are the session's own.

What the reading found.
The repetition in the ten switches is not their dispatch.
A table deletes the dispatch and the scaffolding around it and writes a row, and often a frame, for each operation, so its net is a small share of the switches' lines with a range that crosses zero.
The larger repetition is each case's preamble of checks that the builder and the compile already hold, and one compile rule with an exact attribute type removes it with no table.
The choice of mul_mat's path by the weight's element type and the choice of attention's path are each one operation's own decision, and they stay whole under any table.

How the table stands to the dense block program.
The dense block program wrote one block as a graph of the tensor program's operations and derived its backward graph from a derivative rule for each operation.
It was taken out because its time and memory and its production size failed their conditions.
It named two operations it lacked, a matrix product that contracts over its weight's other width and an attention backward over all heads in one operation.
A table of operations as priced here reorganizes the forward dispatch and adds no derivative rule, no operation and no trainer.
So it supplies neither operation the pilot lacked.
Its size stands where the pilot's failed, as a mechanism whose range of net lines includes growth.
A table that gained a column of derivative rules would be the pilot's rules under another name, with its two failed conditions, so a row filed from this reading excludes such a column.

What a row would be.
A row for the table is not worth filing, and the closing field table-row gives the reason.
The preamble's row is the plan's step shape-reading/launch-checks, and TestNoLaunchRepeatsACompileCheck holds the ten switches free of a recheck, a dimension check and a count check.
